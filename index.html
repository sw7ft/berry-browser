What you are looking at

A ~2024‑era Chromium engine running inside a native BB10 .bar — windowed rendering, real tabs/toolbar chrome, and sites that stock BB10 simply cannot load anymore. The video shows everyday use on a Passport: launching the app, navigating the modern web, and the kind of performance you get when Blink and V8 replace the platform’s ancient WebKit fork.

Why it matters

Berry Browser is the productized end of the chromium-for-bb10 port: TLS with a bundled root store, GPU compositing, ad/tracker blocking at the network layer, YouTube and messaging web apps, BB10 Share handoff, and pin‑to‑home‑screen — packaged so you install it like any other sideloaded BAR.

What Berry Browser is (and is not)

It is an installable BlackBerry 10 application — a Chromium‑powered browser you sideload as BerryBrowserV3-….bar, launch from the home screen, and use as your daily web client on supported BB10 10.3.x hardware.

It is not this GitHub repo’s source tree. Engine code, patches, and build branches (including active berry-v3) live in chromium-for-bb10. sw7ft/berry-browser is the public front door: demo, screenshots, stable download links, and a place to publish experimental BAR files.

The port began as headless content_shell on QNX ARM32 and grew into windowed EGL + Skia UI, BoringSSL, QUIC, and BAR packaging. Berry Browser is that journey turned into something you can hand someone with a cable and a BAR file.

Works alongside BerryCore / berrycore.sw7ft.com when you use rooted qpkg workflows — same ecosystem, different repos.

Quick install (sideload)
  1. Enable Development Mode (Settings → Security and Privacy).
  2. Sideload the .bar with Sachesi, DDPB, or an on-device manager that supports BAR installs.
  3. Launch Berry Browser from the home screen.

Some BerryCore workflows expect a rooted device and qpkg; sideload paths vary by setup — see BerryCore docs if you install via package manager instead.
